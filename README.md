# My-portfolio-App

# 1. サービス概要
- **このサービスはどんなサービスか：**
  ランニング・筋トレ・勉強など、分野ごとに異なる単位（km・時間・回数など）を自由に設定し、自発的な努力の「累積量」と「目標までの差分」を横断的に一元管理できるサービスです。
- **誰の、どんな課題を、どう解決するか：**
  すでに自発的に継続できている社会人を対象に、複数ジャンルの努力成果を統合して数字で可視化することで、「精神論に留まっていた自信をデータで立証する」環境を提供し、適切なペース配分と自分全体のトータルマネジメントおよび総合的な成長実感をサポートします。

---

# 2. このアイデアはどこから生まれたか

## 2-1. きっかけとなった体験・感情
趣味や自己研鑽としてランニング、筋トレ、資格勉強などを日常的に続けている中で、「自分は今日までに累計で何km走り、何時間勉強し、何回筋トレを行ってきたか」振り返りたくなったことがきっかけです。

日々の努力は習慣化しており苦ではない場合でも、これまでの「累積の努力量」と「目標までの現在地」をまとめて可視化する手段がなく、自分がどれだけの積み上げをしてきたのかを感覚でしか把握できないことにモヤモヤとした違和感を覚えました。

## 2-2. なぜそれが「気になった」のか
私自身、目標に向かって努力を積み重ねた結果を定量的なデータを見ることで自信に繋げる性格だからです。

「継続すること（日数）」そのものよりも、「自分がどれだけの量を積み上げてきたか」という客観的な数値データで、自分自身の成長を実感し、自信の根拠になると考えているためです。

# 3. 課題の整理（表面的になっていないか）

## 3-1. 表に見えている困りごと
仕事と並行して取り組む複数の活動（語学勉強・筋トレ・資格取得など）において、それぞれの努力が分散してしまい、「自分全体の総合的な努力量」が数字で同時に可視化できないこと。

## 3-2. 本当に解決したい課題は何か
- **なぜ困るのか？** → 分野ごとに記録がバラバラに存在し、複数の自己研鑽をトータルした「自分の総活動量」や「総合的な成果」が把握できないから。
- **なぜそれが問題なのか？** → 個別の分野の成果しか見えず、複数の努力を並行している「自分全体のトータルな成長実感」が湧きにくいため。
- **なぜ実感が湧かないと問題なのか？** → 多角的な努力に対する自信が「精神論メイン」に留まってしまい、自分自身の総合的な成長を客観的な数字で証明できないから。

→ **本当に解決したい課題：**
すでに複数の自己研鑽を継続している社会人が、複数ジャンルの努力を横断した「総合値」を数字で客観的に証明できず、自信が精神論に留まってしまうことや、自分全体の成長実感が得られないこと。

# 4. 想定ユーザーについて

## 4-1. 想定しているユーザー
「習慣化」の段階はすでにクリアしており、趣味や自己研鑽（資格勉強・トレーニング等）を自発的に日常に組み込んでいる20〜30代の社会人。
- **年齢設定（20代後半〜30代前半）：** 明確な目的意識を持って自主的に勉強や運動を継続する習慣が身についている年代。
- **生活・状況設定：** 平日の仕事終わりや休日に、勉強・筋トレ・ランニングなどを複数こなしており、異なる単位（時間・km・回数・ページ数など）の活動を統合して管理したいニーズがある。
- **環境設定：** 既存の「習慣化アプリ」では個別の数値追跡にとどまりトータルな成長感が得られず、「特化型アプリ」では複数ジャンルを横断した総合的な管理ができないハードルを感じている。

## 4-2. 自分とユーザーの距離
**「自分自身（および過去の自分）」＋「身近なターゲット層（知人）」**

自分自身が「今までの成果を積み上げた数字で把握したい」という課題に直面していた当事者です。
また、当事者目線（主観）のみに偏らないよう、実際にNike Run Club等で運動を記録しつつ資格勉強を行っている知人にMVPの画面を触ってもらい、「複数ジャンルの統合表示や目標との差分が見えることで、手応えや自信に繋がるか」の検証・ヒアリングを実施して改善に活かす予定です。

## 4-3. 実際に使われる可能性について
- **最初のアクション：** 既にアプリやメモ等で何らかの記録をつけている知人や自分自身。
- **代わりに使っているもの：** 
  - スプレッドシート（事務的で自作・管理が面倒）
  - 習慣化アプリ（個別の回数や日数追跡に留まり、複数項目の統合や総合的な管理ができない）
  - 特化型アプリ（分野ごとに分散する）
- **置き換えてまで使う理由：** 単位を自由に設定でき、複数ジャンルの「累計積み上げ量」と「目標との差分」を一箇所で直感的に可視化・立証し、総合的なトータルマネジメントができるから。

## 4-4. ユーザーがサービスを導入して利用するまでのイメージ
- **きっかけ：** 「最近頑張っているけど、結局累計でどれくらいやったんだろう？」と自分の積み上げ量を振り返りたくなった瞬間。
- **最初の一歩：** 目標と独自の単位（km、時間、回など）を登録し、今日の数値を入力する。
- **継続する理由：** 記録するたびにグラフや総数が更新され、「自分の努力の積み上げ」が視覚的な実績・自信として蓄積されていく快感を得られるから。

# 5. 既存サービス・競合調査

## 5-1. 似たサービスの調査
- **Studyplus（学習特化型アプリ）**
  - *できること：* 勉強時間の記録や累計グラフ表示機能が非常に優れており、学習領域の可視化・成長実感には最適。
  - *限界・不満点：* 勉強「単体」のデータは完璧に追えるが、社会人となり勉強と並行して行う運動や他ジャンルの努力を横断・統合して可視化することはできない。
- **Strava / Nike Run Club（フィットネス特化型アプリ）**
  - *できること：* 走破距離やペースなどの累計データが詳細に取得でき、運動領域のモチベーション維持・能力向上には完成された機能とUIを持つ。
  - *限界・不満点：* フィットネス単体としては完璧だが、資格勉強など「時間・回数」で測定する他分野の努力とまとめて自分のトータルな活動量として評価することはできない。
- **Habitify などの習慣化アプリ**
  - *できること：* 日数や回数の記録など、個々の習慣を継続させるための管理機能に長けている。
  - *限界・不満点：* 個別の回数追跡はできても、複数項目を統合して「自分全体の総合的な努力量」として可視化する視点がない。

## 5-2. それでも自分が作りたい理由
私自身、学生時代はStudyplusやNike Run Clubを使用し、単一分野を深掘りできるメリットを実感してきました。
しかし社会人となり、仕事と並行しながら自分の意志で「語学勉強」「筋トレ」「資格取得」など多様な自己研鑽を行うようになると、特化型アプリがどれだけ完璧であっても「1人の人間としてのトータルの成長量・総合値が見えない」という部分に物足りなさを感じるようになりました。

特定領域に特化したツールの良さを理解した上で、努力の幅や目的が広がる今だからこそ必要な「分散したすべての努力の累計を1箇所に集約し、自分という人間全体の成長を蓄積できる総合型ツール」を作りたいと考えたからです。

  ## 5-3. 差別化を「体験価値」で表現する
- **私のアプリの差別化ポイント：**
  社会人となり多様な自己研鑽を自発的に並行している人が、ジャンルの垣根を超えて自分の「総合的な努力量」を把握できる点。
  特定の領域を尖らせる特化型アプリでは得られない、「単一の成果にとどまらず、1人の人間としてトータルでどれだけ成長できているか」を数字で証明し、データから得られる自信と総合的な成長実感を味わえる体験を提供すること。

# 7. このアプリで実現すること
- **MVPで作る機能：**
  - ユーザー認証機能（Deviseによるログイン / 新規登録）
  - 目標（タイトル、目標値、期限日）の登録・管理機能
  - カテゴリ・単位（km、時間、回数など）の登録機能
  - 実績の記録機能（日付、数値、単位、メモ）
  - 累積数値および目標までの差分・必要ペース（残り日数、日数あたりの必要量）の算出・表示機能
  - 複数ジャンルをまとめた「総合値」のダッシュボード表示

**【「総合値」の定義とダッシュボードでの表現方法】**
 
 **総合値の定義**
 本アプリにおける「総合値」は「同時進行で進めている複数の活動を横断して合算・評価し、自分全体の活動量や成長を捉える値」と定義する。
 そのため、単一の単位（km・時間・回数など）ごとの累計値とは区別される。
 
 **総合値の確認方法（ダッシュボードの仕様）**
 1. **目標達成率（%）の並列・集約表示（数値的価値）：** 
    単位が異なる進捗状況を「達成度」という共通尺度を用いてダッシュボードを作成し、全体としての進捗度合いを数値として把握できるようにする。
 2. **実績値の横断・比較グラフ描画（ビジュアル価値）：** 
    日々の継続的な自己研鑽において極端な数値のブレが起きにくい特性を利用し、あえて異なる単位の実績値をベースにした「各活動カテゴリを色分けした積み上げ棒グラフ」を採用する。
    * **本グラフの設計思想：** 
      合算された数値そのものに絶対的な意味を持たせるのではなく、「日々の棒グラフの高さ（全体のボリューム）の増減」によって、自分のトータルの活動量や活動の勢いを相対比較するための指標として機能させる。
    * **フィルター機能によるパーソナライズ：** 
      「どの活動を組み合わせて総合値として見たいか」はユーザーによって異なるため、グラフ表示項目のフィルター機能（絞り込み機能）を実装する。これにより、ユーザーは意図した活動だけを選択してグラフに反映させ、自分にとって意味のあるトータルの活動量比較を行うことができる。

- **本リリースで作る機能：**
  - グラフ表示機能
    - 日別累積値
    - 週間実績
    - 月間実績
    - 目標達成率
  -グラフ表示項目のフィルター機能（絞り込み機能）
    - 単位が異なるデータを1つのグラフに描画する際、数値が乖離して視認性が損なわれることを防ぐため、ユーザーが意図して「筋トレ回数と勉強時間のみ」のようにグラフに含める表示項目を選択・絞り込める仕様を追加。
  - リマインド通知機能

# 8. このアプリの懸念点とその対策

## 懸念点①：複数単位の計算ロジックおよび複合グラフ描画の複雑化
- **何が問題になりそうか：** 単位が自由（km、時間、回数など）なため、データベース設計や集計クエリ（SQL）の設計が複雑になる。また、単位の異なるデータをそのまま可視化する際にグラフの目盛りや視認性が破綻する可能性がある。
- **対策：** 
  - データベース上では記録データ（Records）とカテゴリー・目標（Categories/Goals）の主従関係を明確にし、集計処理はRailsモデル側で集約メソッドとして適切に切り分けてテストコードを書きながら実装する。
  - 表示レイヤーでは、達成率（%）による計算軸の統一と、「各カテゴリを色分けした積み上げ棒グラフ」を採用すること、さらにユーザー指定による「表示項目のフィルター機能」を設けることで、複雑化させないデータ構造と直感的なUI体験を両立させる。

## 懸念点②：レスポンシブ対応とグラフ等のUIデザインの迷い
- **何が問題になりそうか：** スマホやPCなど多様な画面サイズで数値やグラフが崩れやすく、デザインにこだわりすぎて開発が停滞するリスクがある。
- **対策：** MVPの段階ではTailwind CSSを活用して工数を削減し、「日々の入力のしやすさ」を最優先のUI設計にする。

# 10. 技術スタック（手段としての技術）

## 10-1. 使用予定の技術
- **言語 / フレームワーク：** Ruby（3.2.3）, Ruby on Rails（7.1.6）, JavaScript
- **DB：** PostgreSQL（15）
- **認証：** Devise
- **インフラ / 環境：** Docker / Docker compose, Render
- **スタイリング / グラフ：** Tailwind CSS / Chartkick / Groupdate

## 10-2. 技術選定の比較検討
| 候補 | 採用/不採用 | 理由 |
| :--- | :--- | :--- |
| **Ruby on Rails** | 採用 | MVCの仕組みが体系化されており、素早く堅牢なWebアプリを構築できるため。 |
| **PostgreSQL** | 採用 | 本番環境を想定した堅牢なRDBの扱いや、複雑な集計クエリの学習を兼ねるため。 |
| **Devise** | 採用 | ユーザー登録、ログイン、パスワード再設定、メール確認など、Webアプリに必要な豊富な認証機能が標準で揃っており、セキュアな機能を実装できるため。 |
| **Docker / Compose** | 採用 | 開発環境の差異をなくし、本番を見据えた再現性の高いインフラ構築を学ぶため。 |
| **Tailwind CSS** | 採用 | 素早く柔軟にオリジナルデザインを構築でき、クラス名の命名に悩む工数を削減できるため。 |
| **Bootstrap** | 不採用 | あらかじめ用意されたコンポーネントで手軽に構築できる反面、デザインのカスタマイズ性が低いため。 |
| **Chartkick + Groupdate** | 採用 | RailsのActive Recordと連携し、SQLの複雑な日付集計処理（Groupdate）からグラフ描画（Chartkick）までを最小限のコードで安全かつ高速に実装できるため。 |
| **Chart.js（単体利用）** | 不採用 | 高度なカスタマイズが可能な反面、Railsからのデータ受け渡しやJavaScript側の描画ロジック記述量が増え、開発スピードが低下するため。 |

## 10-3. キャッチアップ不足の懸念
- Deviseの機能拡張・カスタマイズ： 標準機能は強固で豊富である一方、独自のビューの変更、ルーティングの調整、メール通知の設定などでつまずかないよう、主要なカスタマイズ手順を事前に検証します。
- Chartkick + Groupdateによる集計・日付の範囲指定やタイムゾーンの扱いなど細かな挙動について理解を深め、MVP開発を通じて段階的に実装・調整を進めていきます。
